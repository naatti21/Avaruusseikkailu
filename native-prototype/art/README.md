# Avaruusseikkailu — Hero station Android renderer benchmark

Status 25 October 2026: experimental / DRAFT. Not an approved game scene.

## Deliverables
- Procedural Blender-authored, original hard-surface 3D station (~1.8 km)
  and 30 m courier; seven shared groups of PBR metallic/rough materials.
- Visible armor segmentation, beveled hard-surface plates, ring trusses,
  lit navigational edges, docking clamps, industrial spine and hangar opening.
- Three fixed-camera beats: reveal, 5-second approach, docking aperture.
- Identical geometry and camera path on Godot Mobile vs GL Compatibility.
- Live overlay on Android: FPS, observed average, p99 frame time, object count.
- Two separately installable ARM64 Android debug APKs from GitHub Actions.
- Existing Docking 0.3 scene/rules intact; no changes to main or web demo.

## Build
Source: native-prototype/art/generate_hero.py. Blender generates two GLB
files inside native-prototype/assets during CI. These binary assets are not
committed. All dimensions are metres; no runtime model scale animation.

Actions: Hero station Mobile versus Compatibility APKs.
Artifact: hero-station-mobile-vs-compat-android-apks (expires after 7 days).

Locally, Blender must run before Godot imports the new scene:
blender --background --python native-prototype/art/generate_hero.py -- --output native-prototype/assets

For test APKs, CI temporarily swaps the app main scene and renderer using
native-prototype/tools/prepare_hero_export.py. Committed project settings
remain Docking 0.3, so existing experiments are not overwritten.

## Asset rights
All geometry and material definitions here are newly generated by the
repository's own Blender Python file. No copied spaceships, screenshots,
third-party materials, downloaded textures, or copyrighted franchise designs.

## Device acceptance protocol (NOT RUN)
On the same Android phone, install both APKs. For each renderer record:
1. Three screen captures or short clips: reveal, approach, docking mouth.
2. Actual Android model, OS, GPU and rendering backend.
3. Warm-device average FPS and p99 frame-time after about 10 minutes.
4. Stutter and heat, memory if measurable, APK size, startup time.
5. Subjective scale, cockpit and station visual realism, docking readability.

Provisional target: steady 30 FPS on midrange Android after warm-up; 60
FPS an aspiration on faster devices. This is NOT a claimed measurement.
A visually poor scene is a FAIL regardless of frame rate.

## Honest limits
This pass uses metallic/rough PBR materials and chamfered modular geometry
rather than the previous primitive grey boxes, but has no baked normal
textures, high-resolution hero atlas, authored weathering or custom LOD yet.
Appearance and thermal performance are unverified until real-device footage
exists. A successful CI export proves neither beauty nor on-phone speed.

Release gate: explicit user visual approval AND device test AND independent
QA before any merge/production integration. This is NOT a release branch.
